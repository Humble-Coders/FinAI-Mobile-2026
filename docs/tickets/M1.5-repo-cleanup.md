# [M1] Clean up the generated scaffolding

## 📖 Story / Why

This repo was created from a Kotlin Multiplatform project template. The generated scaffolding contradicts the architecture in two ways that will mislead anyone who treats it as an example:

1. **It exposes the database to the client.** `sharedLogic/config/Supabase.kt` installs `Postgrest` and `Realtime` and exposes them as `Supabase.postgrest` / `Supabase.realtime`. The architecture forbids this outright: **clients never talk to the database.** Supabase is for **Auth and Storage only**; everything else goes over Ktor to the Render API (PRD §4.2, `CLAUDE.md`).
2. **It ships a shared UI module.** `sharedUI/` is Compose Multiplatform. The architecture is **native UI on both platforms** — Compose on Android, SwiftUI on iOS — with **no shared UI** (`kmp-arch-v2`).

Left in place, the first developer to add a feature will copy the wrong pattern. This ticket removes the misleading scaffolding and leaves a structure that matches the architecture.

## 🧭 Context

- Repo: `FinAI-Mobile-2026`. Kotlin 2.4.10, AGP 9.0.1, minSdk 24, package `com.humblesolutions.finai`.
- Current modules: `androidApp`, `iosApp`, `sharedLogic`, `sharedUI`.
- **Everything currently in the repo is disposable placeholder, not precedent** — this is stated in `CLAUDE.md`. There is no working feature to preserve.
- `sharedLogic/repository/AuthRepository.kt` does email/password against Supabase Auth. Auth will be phone-OTP-plus-Google-plus-Apple (M2), so this file is not the shape we want either.
- SKIE is not configured. It is required: it generates the Swift-facing API, and `@Throws` handling depends on it. Without it, an undeclared Kotlin exception **terminates the iOS process** rather than surfacing to Swift (`kmp-arch-v2`).

## ✅ Scope / What to build

- [ ] **Delete the `sharedUI` module** entirely, and remove `include(":sharedUI")` from `settings.gradle.kts`.
- [ ] Move the Android UI entry point into `androidApp` — `androidApp/.../ui/` with its own Compose setup,
      plus `ui/theme/` for design tokens. A trivial placeholder screen is fine; this ticket ships no product UI.
- [ ] Give `iosApp` a minimal **SwiftUI** entry point in place of anything that referenced the shared UI.
- [ ] **Remove `postgrest-kt` and `realtime-kt`** from `gradle/libs.versions.toml` and from
      `sharedLogic/build.gradle.kts`.
- [ ] Rewrite `sharedLogic/config/Supabase.kt` to install **only `Auth` and `Storage`**, and to expose only those.
- [ ] **Delete `sharedLogic/repository/AuthRepository.kt`** — M2 builds the real one against the actual
      auth flows.
- [ ] Move Supabase URL and anon key out of the hardcoded `SupabaseConfig.kt` constants into **build
      configuration** (Gradle properties / `local.properties` for Android, `Config.xcconfig` for iOS), with
      the placeholder values documented. The anon key is publishable, but committed configuration constants
      are the wrong pattern and the `service_role` key must never come near this repo.
- [ ] **Add SKIE** (`co.touchlab.skie`) to the build, with `skie { analytics { enabled.set(false) } }`.
- [ ] Create the `sharedLogic/commonMain` package structure the architecture expects:
      `model/`, `repository/`, `usecase/`, `data/`, `i18n/`, `config/`, `util/`.
- [ ] Remove the template leftovers: `Greeting.kt`, `GreetingUtil.kt`, and the generated placeholder tests.
- [ ] Update `README.md` to describe this project rather than the KMP template.

## 🎯 Acceptance Criteria

- [ ] `./gradlew :androidApp:assembleDebug` succeeds.
- [ ] `./gradlew :sharedLogic:allTests` succeeds.
- [ ] **The iOS workspace builds** — `xcodebuild` on `iosApp` succeeds. *(Required: SKIE issues surface only in the iOS build — `CLAUDE.md`.)*
- [ ] The `sharedUI` module no longer exists, in the filesystem or in `settings.gradle.kts`.
- [ ] Grepping the repo for `postgrest`, `Postgrest`, `realtime` and `Realtime` returns **no hits**.
- [ ] `Supabase.kt` installs only `Auth` and `Storage`.
- [ ] No Supabase URL or key is hardcoded in a `.kt` source file.
- [ ] SKIE is applied and produces a Swift framework the iOS app links against.
- [ ] The `sharedLogic/commonMain` package structure matches the architecture.
- [ ] The app launches on an Android emulator and in the iOS simulator (placeholder screen is fine).
