# [M3] Read the statement on the device and redact it there

## 📖 Story / Why

On 2026-09-21 statement extraction moved onto the phone (PRD §9). The promise that
makes it worth doing is blunt: **the document never leaves the device.** No upload, no
storage bucket, no OCR vendor. This ticket is the half that keeps that promise — it
turns a file the user picked into redacted text, entirely on-device, and posts only that
text to the API.

Everything downstream depends on the text being good. If this reads a statement badly,
the model downstream invents nothing better; the user just sees rows that are wrong. So
the bar here is accuracy first, and no personal data leaving the phone at all.

## 🧭 Context

- Repo: `FinAI-Mobile-2026`. No brief — M3 is drafted from `docs/ROADMAP.md` and the PRD.
- **Read PRD F2 first** (rewritten 2026-09-21). The old F2 — upload to Storage, a queue,
  a Render worker, AWS Textract, 72-hour deletion — is superseded and must not be built.
- The backend contract is **ticket 3.1** (`Finance-backend` #34): `POST /statements/parse`
  takes `{source_kind, page_count, text, account_id?}` and returns structured rows. Build
  against that contract; the two halves can be built in parallel.
- `kmp-arch-v2` applies as written: the **only** platform-specific code here is the native
  SDK call. Reading a PDF and running OCR are native; deciding what counts as an
  identifier, and stripping it, is a decision — so the redactor is shared Kotlin, tested
  once, and both platforms get identical behaviour by construction.
- Follow `KtorFinancialSetupRepository.kt` for the shared HTTP repository shape:
  `@Throws(ApiException::class, CancellationException::class)` on every public suspend
  fun, `close()` on anything holding a client.
- Libraries (from the 2026-09-21 decision, both free and fully local):
  - **iOS** — PDFKit `PDFDocument` for the text layer; Vision `VNRecognizeTextRequest`
    for OCR. Both well below the app's iOS 18.2 floor.
  - **Android** — **PdfBox-Android** (Apache 2.0) for the text layer, because the
    platform's `PdfRenderer` can only draw pages and has no text API; **ML Kit Text
    Recognition v2, bundled variant** for OCR — statically linked, so it works offline
    with no Play Services dependency. Both below the API 24 floor.

## ✅ Scope / What to build

- [ ] **Shared model** (`sharedLogic/model/`): `ExtractedDocument` — pages, each a list of
      lines with their text and bounding box; plus `SourceKind` (`PDF_TEXT` | `OCR`).
      Coordinates are kept because line order alone loses columns.
- [ ] **Shared redactor** (`sharedLogic/usecase/StatementRedactor.kt`) — a pure function,
      `ExtractedDocument -> String`. Rules, each with its own tests:
      - any run of **7 or more digits** (spaces and dashes ignored) → keep the last 4,
        mask the rest;
      - lines containing an **email address**, a **phone number**, or a **Canadian postal
        code** → dropped entirely;
      - on **page 1 only**, every line **above the first transaction-like line** (one that
        carries both a date and an amount) → dropped. That block is where the name and
        address live, and we never learn the user's name at signup, so there is nothing to
        match against — position is the only signal available.
- [ ] **Read the statement period BEFORE redacting, and send it as a field.** The block the
      rule above drops is also where the **year** lives: statements print `14 Aug` on every
      line and `Statement period: 1 Aug 2026 to 31 Aug 2026` exactly once, at the top. Strip
      it and every date we send is a day and a month with no year — and the backend is
      deliberately built to omit a row it cannot date rather than guess one, so a whole
      statement comes back empty. Find the period first, send it as
      `statement_period_start` / `statement_period_end` on the parse request
      (`Finance-backend` #34), and redact afterwards. A date range is not personal data.
      **Do not try to preserve the period by weakening the redactor** — the block it drops is
      the one with the name and address in it.
- [ ] **Shared repository** — `StatementReader` interface (suspend, returns
      `ExtractedDocument`, `@Throws`) implemented per platform, and
      `StatementImportRepository` + `KtorStatementImportRepository` for
      `POST /statements/parse`, mirroring the financial-setup repository exactly.
- [ ] **Android reader** (`androidApp/data/AndroidStatementReader.kt`): PdfBox-Android for
      a PDF with a text layer; render to bitmap + ML Kit when there is none; ML Kit
      directly for images. Off the main thread, with a progress callback per page.
- [ ] **iOS reader** (`iosApp/repository/IOSStatementReader.swift`): the same three paths
      with PDFKit and Vision. This is the first file in `iosApp/repository/` — create it.
- [ ] **Password-protected PDFs.** Common for bank statements. Prompt for the password on
      the device, unlock locally, and **never send it anywhere**.
- [ ] **Strings** for every user-facing message (`sharedLogic/i18n/`) — no literals in
      platform code.
- [ ] **Measure the size cost** of ML Kit + PdfBox on both platforms and put the numbers in
      the handoff. If Android grows unacceptably, say so rather than quietly shipping it;
      the Play Services variant of ML Kit trades size for a first-use download.

## 🎯 Acceptance Criteria

- [ ] A synthetic text-layer PDF produces one line per statement line, in reading order,
      with coordinates — no OCR involved (proven by asserting `SourceKind.PDF_TEXT`).
- [ ] A synthetic scanned PDF and a PNG screenshot both produce text through OCR.
- [ ] **Redactor tests, shared, table-driven**: account numbers masked to last 4; email,
      phone and postal-code lines gone; the page-1 header block gone; and **every
      transaction line survives untouched** — over-redaction is as much a failure as
      under-redaction. Test names contain no commas (Kotlin/Native).
- [ ] The redacted text sent to the API contains **no digit run longer than 4**, no email
      and no postal code — asserted directly on the string that goes on the wire.
- [ ] The **statement period is found and sent** for a statement that prints it once in the
      header, **and the header itself is still redacted away** — both asserted in one test,
      because the whole point is that the period survives the redaction that removes the
      block it came from.
- [ ] A password-protected PDF unlocks with the right password, reports a clear error with
      the wrong one, and the password appears in no request and no log.
- [ ] Reading a 20-page statement never blocks the main thread; progress is reported per
      page.
- [ ] Nothing logs page text, a line, or the redacted string — counts and page numbers only.
- [ ] **Android compiles and its tests pass, `:sharedLogic:testAndroidHostTest` passes, and
      the iOS workspace `xcodebuild` succeeds.** A shared change is not done until all
      three do (`CLAUDE.md`).

## 🚫 Out of scope

- Any UI — the picker, progress and results screens are **3.6**.
- Persisting transactions, dedup, categorization — **3.3** (backend).
- Uploading the file itself, to anywhere, ever.
- An LLM on the device. Neither Apple's Foundation Models nor Gemini Nano covers the
  installed base, and the model runs server-side for exactly that reason.
