# [M3] Import a statement — the screen

## 📖 Story / Why

This is the screen where M3 becomes real for the user: pick a statement, watch it read,
see what came out. It is also where the product's central privacy claim has to be told
honestly — the file stays on the phone, and we can say that on screen because it is true
(PRD F2, rewritten 2026-09-21).

It is the first time the app does something that takes real time on the device. How that
feels — whether it looks like progress or like a hang — decides whether people trust it
with their bank statements at all.

## 🧭 Context

- Repo: `FinAI-Mobile-2026`. No brief — drafted from `docs/ROADMAP.md` and the PRD.
- **Depends on 3.2**, which does the reading and redacting and owns
  `StatementReader` + `KtorStatementImportRepository`. This ticket is UI and state only —
  **no extraction logic here**.
- Backend: `POST /statements/parse` (#34) then the persist endpoint from 3.3.
- `kmp-arch-v2`: screen + ViewModel + UiState per platform, derived rules as computed
  values on the UiState so they are unit-testable; no business logic in the composable or
  the view.
- The app has no NavHost — routing is `navigation/AppNavigation.kt` (Android) and
  `navigation/RootView.swift` (iOS). Add the route there.
- **First live `403 feature_unavailable`** (carry-over from M1): the client has only ever
  handled it in tests. It must render as a real, localized message here.
- Also live for the first time: **409 `consent_required`** (3.1) and **429
  `import_quota_exceeded`** (3.1). Each needs its own copy — "something went wrong" for a
  quota limit is the kind of thing that generates support mail.

## 🔑 Access & prerequisites

- Write access to `Humble-Coders/FinAI-Mobile-2026`; a Mac with Xcode for the iOS half.
- A running backend with 3.1 deployed, or the fake client, to exercise the states.
- **Synthetic statements only** for testing — never a real one, yours or anyone's.

## ✅ Scope / What to build

- [ ] **Entry point** from the home screen: "Import a statement".
- [ ] **Account step.** Ask which account the statement belongs to, listing the household's
      accounts (3.3) with a way to add one inline. Not optional and not defaulted — an
      import filed against the wrong account silently breaks dedup for both.
- [ ] **File picker** — PDF and images, from Files/Photos on iOS and the document picker on
      Android, plus the camera. Share-sheet entry is a nice-to-have, not required.
- [ ] **The consent step, before the first import ever runs.** Express, unbundled, nothing
      pre-ticked, naming what is sent (redacted text) and what is not (the document).
      Recorded with its policy version by the backend; the 409 from 3.1 is what routes here.
- [ ] **Progress** while the device reads: per-page progress from 3.2, then an indeterminate
      wait for the parse call. Use `AppLoader`; do not invent a second spinner. A 20-page
      statement plus a model call is long enough that a bare spinner reads as a hang — show
      what is happening.
- [ ] **Say the true thing on screen.** A short line stating the document is read on the
      device and never uploaded. Plain, no marketing.
- [ ] **Result.** How many rows were found, how many need review, then straight into 3.7's
      review screen. If 3.7 is not merged yet, a list with a count is enough — say so in
      the handoff rather than blocking.
- [ ] **Every failure state, each with its own copy:** the file cannot be read; the PDF is
      password-protected (prompt, with a retry); nothing that looks like a transaction was
      found; the quota is used up (429, when it resets); consent needed (409); feature
      unavailable (403); network down; the model failed (502, retry is safe because the file
      is still on the phone).
- [ ] **The empty-hands case matters.** When nothing can be read, offer manual entry — it is
      the only other way in, by design.
- [ ] Strings in `sharedLogic/i18n/` for all of the above.

## 🎯 Acceptance Criteria

- [ ] End to end on both platforms: pick a synthetic PDF → progress → rows on screen, with
      the file never leaving the device (assert the only request made is the parse call, and
      that its body carries no digit run longer than 4).
- [ ] The account step cannot be skipped, and a newly created account is selectable without
      leaving the flow.
- [ ] Consent is asked once, before the first import, and never again after it is recorded.
- [ ] Each of 403, 409, 429, 502 and a network failure renders its **own** localized message
      — proven by tests over the UiState, not by inspection.
- [ ] Rotating the device or backgrounding the app mid-read does not lose the picked file or
      restart the read.
- [ ] A password-protected PDF prompts, accepts the password, and the password never leaves
      the device.
- [ ] Nothing logs page text, a row or the redacted payload.
- [ ] **Android compiles and its tests pass, `:sharedLogic:testAndroidHostTest` passes, and
      the iOS workspace `xcodebuild` succeeds.**

## 🖼️ UI standards

**No design is provided for this screen** (manager decision, 2026-09-21) — build it against
what M2 established and the app's design tokens. That is a licence to design it, not a
licence to skip these.

- [ ] **Reuse what exists.** `ui/theme/` tokens on Android and `Brand` on iOS, `AppLoader` /
      `LoaderHost` for waits, `GradientButton`, the setup wizard's field styling
      (`AmountField` / `WizardField` in `ui/setup/SetupScreen.kt`, `SetupView.swift`). No
      one-off colours, no second loader, no duplicated field.
- [ ] **Light and dark.** Every colour from a token defined in both modes; verify in both.
- [ ] **Native components first** — Material on Android, HIG on iOS. Don't hand-roll a list,
      a sheet, a picker or a dialog the platform gives you. Where the design genuinely needs
      something custom, say so in the handoff rather than diverging silently.
- [ ] **Edge-to-edge, with correct insets.** Backgrounds bleed under the system bars; no
      content or tap target under the status bar, notch, home indicator or Android gesture
      bar.
- [ ] **Responsive** small phone → large phone → tablet, both orientations; cap content
      width and centre on large screens. Text ellipsizes cleanly rather than clipping or
      pushing the layout — merchant names are long and unpredictable.
- [ ] **Keyboard done properly** — number pad for amounts with a Done accessory (number pads
      have no return key), Next/Done actions wired, the focused field never hidden behind
      the keyboard.
- [ ] **Loading, empty, error and disabled states** for everything that fetches or submits.
      Errors inline and localized, never a raw message dumped on screen.
- [ ] **State survives** rotation, configuration change and process death — nothing typed is
      lost.
- [ ] **Accessibility**: labels on every interactive element, logical focus order, 48dp /
      44pt targets, layouts that hold at the largest font scale, AA contrast.
- [ ] **No hardcoded strings** — everything through `sharedLogic/i18n/`.
- [ ] **Verify on the range**: smallest and largest supported device, light and dark, largest
      font scale, and every state.
