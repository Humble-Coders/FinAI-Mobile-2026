# [M4] Budget screens: see the month's budget and change any line

## 📖 Story / Why

The budget is generated from what the household actually spent (backend 4.1), so nobody has
to build one. But PRD F4 is explicit that **a manual override is always available**: the
generated number is a starting point, and the person decides. This ticket is where they see
the whole budget for a month, category by category with spending against each line, and
change any line or put it back to the suggestion.

Two things must hold:

- **What the user typed is what they see.** It never drifts back to a suggestion behind
  their back; the server keeps user-set lines through regeneration.
- **Over budget is unmistakable**, and never conveyed by colour alone.

## 🧭 Context

- Repo: `FinAI-Mobile-2026`. **No brief.** Drafted from `docs/ROADMAP.md` (4.5) and PRD
  **F4**, **F8** and **F9** (the free plan's "manual budgeting").
- **Builds on PR #45**, which must be merged. That PR adds:
  - the bottom bar (Android `navigation/AppNavigation.kt` `HomeBar`; iOS
    `navigation/RootView.swift` `tabs`)
  - the shared transaction editor pattern (`ui/edit/TransactionEditor.kt`;
    `CorrectionSheet` in `ReviewView.swift`)
  - `CategoryVisuals` (category icon and tint on both platforms)
  - the green-field screens (`GreenField.kt` / `Field`)
- **Server side is 4.1:**
  - **`GET /budgets/{YYYY-MM}`** returns `learning`, or `ready` with:
    - `lines`: `category_id`, `slug`, `name`, `suggested`, `allocated`, `is_user_set`, `spent`
    - `savings` and `debt` lines
    - `total_allocated`, `total_spent`, `expected_income`, `shortfall`
    - `uncategorised_spent` and `uncategorised_count`
  - **`PUT /budgets/{YYYY-MM}/lines/{category_id}` `{amount}`** sets a line, creating it if
    absent.
  - **`DELETE .../lines/{category_id}/override`** resets a line to its suggestion.
  - **Errors:** `403 feature_unavailable`, `404 not_found`, `422 invalid_amount`,
    `422 not_budgetable`, `422 invalid_month`, `422 month_in_future`.
- **Navigation (manager decision, 2026-10-04, PO to confirm at `/review-ticket`):** a fourth
  tab, **Budget**, between Transactions and Review: Home · Transactions · Budget · Review.
  The tab is drawn only when capabilities enable `auto_budget`. Home's "See budget" link
  (4.4) selects it.
- **Design: none provided. Manager decision: "match Home".** Use the same green field and
  white sheet as "Your transactions", the category tiles and tints from `CategoryVisuals`,
  and the editor sheet pattern from the transaction editor. No new colours or card styles.
- **The screen:**
  - **Header (in the field):** a month selector (current month first, then earlier months),
    "Spent $X of $Y", a progress bar, and:
    - expected income
    - the savings line ("Set aside $Z")
    - if there's a `shortfall`, a clear line: "Your budget is $N more than your income"
  - **Lines (in the sheet):** one row per category, made up of:
    - the category tile, the name, "$spent of $allocated", and a progress bar
    - an **"Over by $N"** label when over (amber or red **plus** text)
    - a "Suggested $S" note when the line is user-set
  - **Then:**
    - the debt line ("Debt payments, at least your minimums")
    - an "Add a category" row
    - when `uncategorised_count > 0`: "12 transactions aren't filed yet, so they aren't in
      your budget", which opens the Review tab
  - **Learning:** below the threshold, the "Still learning your patterns" card (the same
    one as 4.4, from shared strings) with progress and a nudge to import.
- **Editing a line:** tap a row to open a sheet, in the transaction editor's style, with:
  - an amount field (decimal pad, currency symbol, with **Done** on the keyboard)
  - "Use suggestion ($S)" when user-set
  - Save and Cancel

  "Add a category" opens a category picker, listing system categories except `income` and
  `transfers` plus the household's own, then the same amount sheet.
- **Validation is shared:** `BudgetEdit.blockingReason(draft)` returns one reason or none:
  empty, not money, negative, too precise, or unchanged. The disabled Save button, the inline
  notice and the use case's thrown error all read that same function (`CLAUDE.md` → Blocking
  reasons).
- **After a save or a reset:** re-read the month and tell Home, so its budget card updates.
  Either reuse the `LedgerChanged` signal or add a `BudgetChanged` one, the same on both
  platforms. A budget change doesn't move the ledger, so a dedicated signal is cleaner; the
  developer decides and says which in the handoff.
- The client **never computes** a total, a remainder or an over amount. It shows the server's
  figures. Progress fractions for the bars are a display fold in shared code.

## 🎯 Acceptance Criteria

- [ ] With 4.1 deployed, the Budget tab shows the current month's budget: totals, savings,
      shortfall when present, each line with spent of allocated, and over-budget lines labelled
      in words.
- [ ] **Changing a line sticks:**
      - set Groceries to $500 and save
      - the line shows $500 and "Suggested $440"
      - leave and return, import more transactions, read again
      - it is still $500
- [ ] "Use suggestion" puts a user-set line back to the server's current suggestion.
- [ ] "Add a category" adds a line for a category with no history. `income` and `transfers`
      aren't offered.
- [ ] Save is disabled with the right inline reason for:
      - empty
      - not a number
      - negative
      - more decimals than the currency allows
      - unchanged

      The use case refuses the same inputs with the same reason, read from one shared function.
- [ ] A failed save (network, `422`) keeps the sheet open with the user's input and the error.
      Nothing is half-applied.
- [ ] Below the threshold, the tab shows the learning card with correct progress, and no
      empty budget.
- [ ] With `auto_budget` disabled in capabilities, the tab doesn't appear. A `403` from the
      server shows its own message.
- [ ] After a save or reset, Home's budget card (4.4) shows the new figure on return, with no
      app restart.
- [ ] "Transactions not filed" opens the Review tab.
- [ ] Previous months are reachable from the month selector and show their kept budgets.
- [ ] No figure is computed on the client.
- [ ] `./gradlew ktlintCheck`, Android build and tests, and the iOS `xcodebuild` all pass.
      The PR states all three.

## 🖼️ UI standards

**No design is provided. Build it against the existing Home and "Your transactions" design.**
The PM may supply mockups at `/start-ticket`. **Ask before building**; if they exist, match
them exactly.

- [ ] **Design system:** reuse `Field`, `Waves`, `FieldVectors`, the sheet, `CategoryVisuals`
      tiles and tints, and the editor sheet pattern. No one-off colours or sizes, and no copied
      components.
- [ ] **Light and dark themes:** every colour from tokens in both modes. Check the field, the
      list, the editor and the picker in both.
- [ ] **Native components:** a bottom-bar tab (`NavigationBarItem` / `TabView` item). The
      editor is `ModalBottomSheet` / `.sheet` (iOS `Form`). The picker is a native list sheet.
      Progress bars are native where possible; anything that can't be is flagged.
- [ ] **Edge-to-edge and insets:** the field runs under the status bar. Content clears the
      status bar, the bottom bar and the gesture area. The editor sheet stays above the
      keyboard.
- [ ] **Responsive:** small and large phones, landscape. Content width capped at 560.
- [ ] **Keyboard:**
      - The amount field uses the **decimal pad**, with the currency symbol.
      - An on-keyboard **Done** (iOS has no return key on the pad) dismisses it.
      - **Save** submits.
      - The focused field and its error stay visible above the keyboard.
- [ ] **Truncation:** long category names ellipsize on one line. Amounts never clip.
- [ ] **States:**
      - **loading:** the coin loader on first load
      - **refreshing:** figures stay up when switching months
      - **learning:** the card
      - **error:** inline, with retry; a failed refresh keeps the last figures
      - **disabled Save:** with its reason
      - **saving:** busy button, inputs locked
- [ ] **Preserve state:** an amount being typed survives rotation and process death (saved
      state, as manual entry does).
- [ ] **Accessibility:**
      - Each line reads "Groceries, spent $380 of $440" and, when over, "over by $40".
      - Touch targets are at least 48dp / 44pt.
      - Layouts hold at the largest font scale.
      - Over budget is never colour alone.
- [ ] **Motion:** bar animations respect reduce-motion.
- [ ] **i18n:** every string through `sharedLogic/i18n`, and no literals in platform code.
- [ ] **Architecture:** native UI per platform, decisions and folds in `sharedLogic`, VMs
      drive rendering (`kmp-arch-v2`).
- [ ] **Verify** on the smallest and largest phone, light and dark, and the largest font
      scale, in every state above.
