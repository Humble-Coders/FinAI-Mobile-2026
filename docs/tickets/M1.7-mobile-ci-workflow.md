# [M1] Add a CI workflow for the mobile apps

## 📖 Story / Why

Every mobile ticket from here on has **`xcodebuild` succeeding** in its definition of done, because **SKIE breakages appear only in the iOS build** — an undeclared `@Throws` compiles fine on Android and terminates the iOS process at runtime. Right now nothing enforces that except a developer remembering to build locally on a Mac.

The PRD commits Android and iOS to shipping **together** in v1 with feature parity. That commitment is only as good as the thing checking it. Without CI, iOS drifts quietly: someone lands a shared-code change on a Linux machine, Android is green, and the break is found days later by whoever next opens Xcode.

The backend already has this gate (`Finance-backend` #13). This closes the same gap on mobile.

## 🧭 Context

- Repo: `FinAI-Mobile-2026`. Kotlin 2.4.10, AGP 9.0.1, minSdk 24 / compileSdk 36, package `com.humblesolutions.finai`.
- Modules after ticket **#5**: `androidApp`, `iosApp`, `sharedLogic`. (`sharedUI` is deleted by #5 — do not add a job for it.)
- SKIE is added by #5 and is what makes the iOS job non-optional.
- The project pins its build JVM in `gradle/gradle-daemon-jvm.properties` — **CI must match it** rather than picking a version. Mismatched JDKs are how the backend's first CI-adjacent failure happened (Python 3.14 vs 3.12).
- `iosApp` uses CocoaPods (`iosApp/Podfile`, `kotlinCocoapods` plugin), so the iOS job needs a `pod install` step before `xcodebuild`.
- **The repo is public**, so GitHub-hosted macOS runners are currently free. If it ever goes private, macOS bills at **10× the Linux rate** and the iOS job becomes the expensive part — worth revisiting then, not now.

## 🔑 Access & prerequisites

- Write access to `Humble-Coders/FinAI-Mobile-2026`.
- **No secrets required.** Nothing in this workflow signs a build, contacts Supabase, or calls the API — Supabase values are placeholders after #5. If a future job needs signing credentials, that is a separate conversation with the manager.
- A Mac is **not** needed to write this ticket — GitHub's macOS runners do the iOS build — but the developer should expect a few iterations against CI logs.

## ✅ Scope / What to build

- [ ] `.github/workflows/ci.yml`, triggered on pull requests to `main` and pushes to `main`.
- [ ] **Android job** on `ubuntu-latest`:
      - JDK matching `gradle/gradle-daemon-jvm.properties`
      - Gradle caching
      - `./gradlew :androidApp:assembleDebug`
      - `./gradlew :sharedLogic:allTests`
- [ ] **iOS job** on `macos-latest`, running on **every pull request** (not path-filtered):
      - JDK as above; Gradle caching
      - Build the shared framework so SKIE runs
      - `pod install` in `iosApp/`
      - `xcodebuild` on the `iosApp` workspace for a simulator destination, `CODE_SIGNING_ALLOWED=NO`
- [ ] Pin the **Xcode version** explicitly (e.g. via `maxim-lobanov/setup-xcode`) rather than inheriting whatever the runner image ships — an image bump must not silently change the toolchain.
- [ ] Both jobs run in parallel; the workflow fails if either fails.
- [ ] Add a CI status badge to `README.md`.

## 🎯 Acceptance Criteria

- [ ] Opening a pull request runs both jobs automatically.
- [ ] The Android job builds the debug APK and runs `sharedLogic` tests.
- [ ] The iOS job completes `xcodebuild` successfully on a simulator destination.
- [ ] **The iOS job actually catches a SKIE failure**: verify once by removing `@Throws` from a throwing public suspend function (or equivalent), confirming CI goes red, then reverting. *This is the whole purpose of the ticket — do not skip this check.*
- [ ] The workflow requires **no repository secrets**.
- [ ] The JDK version in CI matches `gradle/gradle-daemon-jvm.properties`.
- [ ] The Xcode version is pinned in the workflow, not inherited.
- [ ] A red job blocks the PR (branch protection can be configured separately by the manager).
- [ ] The README badge reflects real status.

## 🚫 Out of scope

- **Kotlin linting** (ktlint / detekt). Deliberate: #5 is about to rewrite most of this repo, so linting now means formatting code that is being deleted. Add it once the structure settles — worth a follow-up ticket.
- Signed release builds, TestFlight or Play uploads, any distribution.
- Running instrumented tests on emulators or simulators — slow and flaky; unit tests only for now.
- Backend CI — already covered by `Finance-backend` #13.
- Branch-protection rules (manager configures these in repo settings).

## 🔗 Dependencies

- **Best landed after #5**, which deletes `sharedUI` and adds SKIE. Written before #5 it would reference a module that is about to disappear and could not test the SKIE gate.
- Blocks nothing, but every mobile ticket after it is safer for existing.
