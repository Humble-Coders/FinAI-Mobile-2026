# [M1] Build the shared API client and repository layer

## 📖 Story / Why

Every feature from M2 onwards reads and writes through the Render API. This ticket builds the layer they all sit on, and gets its shape right once.

Because the backend is **plain HTTP + JSON**, the architecture is unusually simple here: **repositories are implemented once in `sharedLogic/data/` with Ktor**, not per platform. Android and iOS share the same implementation, not just the same interface. The per-platform `data/` and `repository/` folders exist only for genuine native work — file pickers, camera, push tokens, biometrics (`kmp-arch-v2`).

The load-bearing rule: **the client never talks to the database.** Supabase provides the session and its JWT; every business call goes to the Render API carrying that token.

## 🧭 Context

- Repo: `FinAI-Mobile-2026`. Ticket 1.5 leaves `sharedLogic/commonMain` with the right package structure, Supabase reduced to Auth + Storage, and SKIE configured.
- Ktor is already in the version catalog: `ktor-client-core`, `ktor-client-okhttp` (Android), `ktor-client-darwin` (iOS).
- Live API: `https://finai-api-7bae.onrender.com`. `GET /healthz` and `GET /readyz` respond today; `GET /capabilities` requires a bearer token and currently returns a stub payload (backend ticket 1.3 makes it real — **the response shape is final**, so this ticket can build against it now).
- Auth is Supabase-issued JWTs from phone OTP, Google, or Apple. All three produce the same kind of token, so the client only ever attaches whatever the current session holds.

## 🔑 Access & prerequisites

- Write access to `Humble-Coders/FinAI-Mobile-2026`.
- **A Mac with Xcode** — the iOS build is part of the definition of done.
- Supabase **project URL and anon key** for the dev environment — from the manager or the Render `finai-shared` group. The anon key is publishable and safe in the app; **the `service_role` key must never enter this repo.**
- Ticket **1.5 merged**.

## ✅ Scope / What to build

- [ ] A configured Ktor `HttpClient` in `sharedLogic/data/`: JSON via `kotlinx.serialization`, timeouts,
      logging that is **disabled or redacted in release builds** (never log tokens or response bodies —
      responses carry financial data).
- [ ] **Bearer-token auth**: attach the current Supabase session's JWT to every request, refreshing via the
      Supabase SDK when it has expired. A request must never be sent with a stale token.
- [ ] **Base URL from build configuration**, not a hardcoded constant, so environments can differ.
- [ ] **Typed error mapping**: HTTP status → a sealed error type in `sharedLogic` (unauthorized, forbidden /
      feature-not-available, not found, validation, server, network). Screens must never parse status codes.
- [ ] `@Throws` on **every public suspend function** that can throw — an undeclared Kotlin exception
      **terminates the iOS process**. Include and rethrow `CancellationException`; never swallow it.
- [ ] A **`ThrowsAnnotationGuardTest`** (jvmTest source scan) that fails the build when a public suspend
      function containing `require` / `check` / `error` / `throw` lacks `@Throws`.
- [ ] `sharedLogic/model/` — data classes for the capabilities payload and the user/household response,
      with **default values on all fields** (wire tolerance and SKIE ergonomics), and enums owning their wire
      mapping via `fromWire(...)` with a safe fallback.
- [ ] `sharedLogic/repository/` — interfaces (`AuthRepository`, `CapabilitiesRepository`) with `suspend`
      one-shots and `Flow` for live data.
- [ ] `sharedLogic/data/` — Ktor implementations of those interfaces. **Repositories are never singletons**;
      a repo owning a client exposes `close()`.
- [ ] `sharedLogic/i18n/` — `Strings.kt` (keys) and `EnglishStrings.kt` (values), seeded with the error
      messages this layer can surface. **No user-facing string literals in platform code.**
- [ ] Wire it end to end on both platforms: a screen that signs in with a test session, calls
      `/capabilities`, and renders the result — proving the whole path works. Throwaway UI is fine.
- [ ] Tests in `commonTest` for error mapping and model deserialization, including unknown enum values and
      missing fields. **Test names must contain no commas** (they fail native test targets).

## 🎯 Acceptance Criteria

- [ ] `./gradlew :androidApp:assembleDebug` and `:sharedLogic:allTests` succeed.
- [ ] **`xcodebuild` on `iosApp` succeeds** — required; SKIE breakages appear only here.
- [ ] The Android app calls `/capabilities` with a real token and renders the payload.
- [ ] The iOS app does the same via SwiftUI.
- [ ] An expired token triggers a refresh and the request still succeeds.
- [ ] A 403 surfaces as the typed feature-unavailable error, not a raw status code.
- [ ] `ThrowsAnnotationGuardTest` passes, and **fails** when `@Throws` is deliberately removed from a throwing public suspend function (verify once, then revert).
- [ ] Release builds log no tokens and no response bodies.
- [ ] Grep confirms no `postgrest` / `realtime` usage and no direct database access.
- [ ] No user-facing string literal exists in `androidApp` or `iosApp`.
- [ ] The base URL comes from build configuration.

## 🚫 Out of scope

- Real authentication flows — phone OTP, Google, Apple are **M2 (2.3)**. This ticket may use a test session obtained by any convenient means.
- Any production screen, navigation, or design work — the demo screen is throwaway.
- Repositories for features that don't exist yet (transactions, budgets, goals) — each arrives with its milestone.
- Offline caching or persistence.
